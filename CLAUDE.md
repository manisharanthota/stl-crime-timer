# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Rules

- Write tests for every module.
- Never call real external APIs in tests (Anthropic, crime data sources, etc.); mock them.
- Only work on the chunk the user asks for. The project is built one chunk at a time per `docs/design.md`; don't implement future chunks early.

## Commands

Use the virtualenv at `.venv` (`.venv\Scripts\activate` on Windows).

```bash
pip install -e ".[dev]"                  # install app + test deps
uvicorn api.main:app --reload            # run the API
pytest                                   # all tests
pytest tests/test_health.py::test_health # single test
alembic upgrade head                     # apply migrations
alembic revision --autogenerate -m "msg" # new migration
python seed.py                           # load sources.yaml into sources (skips known urls)
python -m fetchers                       # fetch all active sources once into raw_items
python -m classifier                     # classify all status=new raw_items once (needs GEMINI_API_KEY)
python -m matcher                        # link all unlinked in-STL crime classifications into incidents once
python -m jobs once                      # run fetch -> classify -> match once (live network + LLM)
python -m jobs schedule                  # run it every PIPELINE_INTERVAL_MINUTES (+ watchdog every 5 min); Ctrl+C stops gracefully
python -m alerts test                    # send a test alert to ALERT_WEBHOOK_URL (log only if unset; ignores cooldowns)
python -m classifier.eval                # score the live LLM on tests/fixtures/eval_headlines.yaml (manual, not pytest; cached, --no-cache to bypass; --model NAME to score another model, e.g. the fallback)
```

## Architecture

- `config.py` — `get_settings()` loads `.env` (python-dotenv) into a cached Pydantic `Settings` (`database_url`, `anthropic_api_key`, `llm_provider`, `gemini_api_key`, `gemini_model`, `gemini_fallback_model`, `gemini_rpm`, `match_location_threshold`, `pipeline_interval_minutes`, `admin_token`, `alert_webhook_url`, `alert_on_new_incident`, `alert_cooldown_hours`). Read config through this, not `os.getenv`.
- `db.py` — SQLAlchemy 2.0 `engine`, `SessionLocal`, declarative `Base`, and `UTCDateTime`. All models subclass `Base`; every datetime column uses `UTCDateTime`.
- `timeutil.py` — all datetimes are stored and compared in UTC. `to_utc()` treats naive input as America/Chicago (DST-aware); `to_local()` converts to St. Louis time and is for display only (and the LLM prompt). `UTCDateTime` applies `to_utc` on write (naive UTC on SQLite, timestamptz on Postgres) and returns aware UTC on read.
- `models.py` — `Source`, `RawItem`, `Classification`, `Incident`, `IncidentItem`, `PipelineRun`, `JobLock`, `AlertSent`, plus `hash_url()` (sha256 used for `raw_items.url_hash`). Enum-like columns are non-native `Enum`s with CHECK constraints (portable SQLite → Postgres). Incident status `merged` means folded into `merged_into_id`; merged incidents are never counted or matched. `db.py` enables SQLite foreign keys on every connection.
- `seed.py` — `seed_sources(session, path)` inserts sources from `sources.yaml` whose url isn't already stored.
- `alembic/env.py` — takes the DB URL from `config.py` (the value in `alembic.ini` is ignored) and uses `Base.metadata`; model modules must be imported there for autogenerate to see them. On SQLite it turns foreign keys off for the run (batch table rebuilds would otherwise fail on references) and fails the command if `PRAGMA foreign_key_check` finds violations afterwards; SQLite migrations commit as they go, so that check reports but can't roll back.
- `api/` — FastAPI `app` in `main.py`; response models in `schemas.py` (datetimes serialize as UTC `...Z`); read queries in `queries.py`. Everything is computed per request from `status=confirmed` incidents (no caching), so confirm/reject shows up immediately. `/timer` = latest confirmed incident overall and per crime type (shooting = `crime_type=shooting OR was_shooting`, so a fatal shooting counts for both shooting and homicide; `/stats` uses the same rule) with `seconds_since` (clamped >= 0; `last: null` when none). `/incidents?limit=20` (1-100) = recent confirmed incidents with linked articles. `/stats` = longest gap between consecutive confirmed incidents overall and per type, counting the open gap up to now (`ongoing: true`). `/health` = latest `pipeline_runs` row. `/admin/*` needs header `X-Admin-Token` == `ADMIN_TOKEN` (401 missing/wrong, 503 if unset): `GET /admin/review`, `POST /admin/incidents/{id}/confirm|reject`, `POST /admin/incidents/{id}/merge?into={other}` (`matcher/merge.py`: moves links, keeps the earliest reported time, ORs `was_shooting`, confirms if either was, marks the source `merged`; 400 self, 404 missing, 409 already merged / target rejected / incompatible types). `/` serves `api/static/index.html` (single file, no build; times shown in America/Chicago, ticks every 1s, refetches every 60s). Dependencies `get_session`, `get_now`, `get_admin_token` are overridden in tests.
- `fetchers/` — `BaseFetcher` + `RSSFetcher` (httpx fetch, 15s timeout + User-Agent, feedparser parse; covers news and RSS.app feeds). `runner.run_fetchers(session, client=None)` loops active sources, each isolated: success sets `last_success_at`/resets `fail_count`, failure rolls back, increments `fail_count`, logs. Items dedup on `hash_url(normalize_url(url))` (query/fragment/trailing slash stripped). Tests inject an `httpx.MockTransport` client and use XML fixtures in `tests/fixtures/feeds/`.
- `classifier/` — built for the Gemini free tier (5 RPM, 20/day). `prefilter(item)` (word-boundary keyword regex) runs first; misses are saved as `is_crime=False`, `model="prefilter"` with no LLM call. The rest go up to 10 per request (`classify_batch`): the prompt is a JSON array keyed by `raw_item_id`, the response is `list[BatchResult]`, and each element is validated separately. A bad or missing element gives that item `retries += 1` and leaves it `new`; once `retries` reaches 3 it's marked `failed`. A response that isn't a JSON array is retried once. `RateLimiter` spaces requests `60/GEMINI_RPM + 1`s apart. `request_llm` policy: 429 with `retryDelay` < 2 min → wait and retry; longer/missing → `QuotaExhausted`; 503/other errors → backoff 5/15s (kept short: failed attempts may count toward quota), then the batch stays `new` (logged as one warning line, no traceback). With `GEMINI_FALLBACK_MODEL` set (`_Models` in `classify.py`): a primary still on 503 (`ModelOverloaded`) gets one fallback request for that batch (no backoff), and the next batch starts on the primary again; a primary quota 429 switches the rest of the run to the fallback (`switched_quota`, one attempt per batch); the run stops (`stopped_quota`, items stay `new`, retries untouched) only when every model has hit its quota. `classifications.model` records which model answered and the `fallback` count says how many. An injected `llm` only gets a fallback if one is passed too. `GeminiClient` sets the SDK's `HttpRetryOptions(attempts=1)` so only our retries apply; eval stays primary-only. `LLMClient` ABC with `GeminiClient` maps SDK errors to `RateLimitError`/`ServiceUnavailableError`/`LLMError`. The output has `was_shooting` (a fatal shooting is `crime_type=homicide, was_shooting=true`; the schema forces it true for shootings and false for burglaries/non-crime), `is_followup` (victim identified, vigil, arrest... about a crime within 7 days counts as a crime, with the original crime's `occurred_at`; court news never does), `neighborhood` (normalized onto the 79 official names in `matcher/neighborhoods.py`, else null), and `time_precision` (`exact` = a stated clock time; `date_only` = only a day or part of day, e.g. a guessed 00:00; `unknown` = no time). Only `exact` times count as reported; the others are estimates. `prompt.py` holds `SYSTEM_PROMPT` + `PROMPT_VERSION` (bump on any wording change). `eval.py` caches results in `.eval_cache.json` (`--no-cache` to bypass). Tests inject a fake `LLMClient`, `RateLimiter(0)`, and a recording `sleep`.
- `matcher/` — `match_pending(session, threshold=None)` takes the newest classification of each raw_item not in `incident_items` with `is_crime AND in_stl` (others ignored). Missing `occurred_at` falls back to `published_at` and sets `incidents.time_estimated`, and a non-`exact` `occurred_at` is estimated the same way; items are processed oldest first. A follow-up with no `occurred_at` is never linked (`skipped_followup_no_time`): its publish date can be days after the crime. Merge needs compatible type (same, or shooting/homicide → upgraded to homicide), `occurred_at` within ±6h (±24h if the incident's or the item's time is estimated), and the same non-null `neighborhood` OR `location_similarity` (normalized, rapidfuzz `token_set_ratio`; null location never matches) ≥ `MATCH_LOCATION_THRESHOLD` (default 85). Merged incidents are never candidates. `incidents.was_shooting` is true if any linked item has `was_shooting` or `crime_type=shooting`, and stays true through the shooting → homicide upgrade. Merges keep the earliest time (a reported time beats an estimated one) and confirm on any item with confidence ≥ 0.8, never downgrade. Rejected incidents are never modified: an item matching one (and no live incident) stays unlinked. Idempotent because only unlinked items are selected. Each run ends with `refresh_incidents`: live incidents re-read their linked items' newest crime classifications (if any has an `exact` time, the incident takes the earliest one even if that's later, so a stated 00:40 beats a guessed midnight; with none it's left alone; `was_shooting` only turns on; empty location/neighborhood filled).
- `jobs/` — `run_pipeline(session_factory=None, steps=None, stop_event=None)` runs `STEPS` (fetch → classify → match), each in its own session and try/except: a failing step is rolled back, its error recorded, and later steps still run. Every run that gets the lock writes a `pipeline_runs` row (`running` → `success`/`partial`/`failed`, per-step JSON counts and error text); a run that can't get the lock returns None and writes nothing. A classifier quota stop is not an error (it shows as `stopped_quota` in the counts). `lock.py` is a `job_locks` row with a 30-minute expiry, refreshed between steps; an expired lock is taken over with a conditional UPDATE, and `release` only deletes the caller's own lock. `scheduler.py` runs work off the main thread: APScheduler `BackgroundScheduler` (`max_instances=1`, `coalesce=True`, first run immediately). The first Ctrl+C sets `stop_event` (the current step finishes, the rest are recorded `skipped: shutdown`) and a second one force-exits. `logsetup.setup_logging()` (CLI only) logs to the console and `logs/pipeline.log` (rotating), with UTC timestamps. Tests pass fake steps and a `StaticPool` session factory (`session_factory` fixture).
- `jobs/` alert hook: after the lock is released, `run_pipeline` calls `alert_check` (default `alerts.checks.check_after_run`) in its own session; any error there is only logged. `scheduler.py` also runs `alerts.checks.run_watchdog` every 5 min as a separate job. `UTCFormatter` redacts Discord webhook tokens (httpx logs request URLs at INFO).
- `alerts/` — Discord webhook alerts. `notify.send(text)` posts `{"content"}` (cut to 2000 chars, `allowed_mentions` off), returns False on any failure and never raises; with `ALERT_WEBHOOK_URL` empty it only logs (counts as sent). `store.py` = `alerts_sent` rows keyed by alert key: a key is sent again only after `ALERT_COOLDOWN_HOURS` (default 6) or once resolved; a row is written only after a successful send, so failed sends retry next run. `checks.py`: `source_down:{id}` (active source `fail_count >= 5`; recovery when back to 0), `llm_quota` (`classify_counts.stopped_quota`, i.e. every model out; recovery on a run that classified something), `stuck_new` (> 20 `new` raw_items older than 2h; cooldown only), `review:{id}` (incidents created this run in `review`) and `incident:{id}` (created `confirmed`, only with `ALERT_ON_NEW_INCIDENT`) are one-shot per incident and batched into one message; `watchdog` (no `status=success` run in 30 min, measured from the later of the last success and scheduler start, so partial runs alone do alert; recovery on the next success). Each check is isolated. Tests use an `httpx.MockTransport` webhook; the autouse `no_real_alerts` fixture in `conftest.py` blanks the alert env vars and makes `notify.make_client` raise.
